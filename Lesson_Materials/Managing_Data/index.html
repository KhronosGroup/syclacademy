## Managing Data
## Learning Objectives * Learn about the USM model for managing data * Learn how to allocate, transfer and free memory using USM. * Learn how to access data in a kernel function
#### Memory Models
* In SYCL, the USM (unified shared memory) model manages data using familiar C++ pointers. * Memory is allocated, transferred and freed explicitly through the SYCL `queue`.
#### CPU and GPU Memory
* A GPU has its own memory, separate to CPU memory. * In order for the GPU to use memory from the CPU, the following actions must take place (either explicitly or implicitly): * Memory allocation on the GPU. * Data migration from the CPU to the allocation on the GPU. * Some computation on the GPU. * Migration of the result back to the CPU.
#### CPU and GPU Memory
* Memory transfers between CPU and GPU are a bottleneck. * We want to minimize these transfers, when possible.
#### Allocation Types
* There are different ways USM memory can be allocated: host, device and shared.
| Type | Description | Access host | Access device | Nominal location | |--------|---------------------------------|----------------|----------------|----------------------| | device | device global allocations | ✗ | ✓ | device | | host | host allocations | ✓ | ✓ | host | | shared | Allocations shared between both | ✓ | ✓ | migrates as required |
#### Malloc Device 

#include <sycl/sycl.hpp>
#include <vector>

int main() {
  constexpr int N = 5;
  std::vector<int> a{1, 2, 3, 4, 5}, b{5, 4, 3, 2, 1}, r(N);
  std::vector<int> expected{6, 6, 6, 6, 6};
  sycl::queue q;

  int *devA = sycl::malloc_device<int>(N, q);
  int *devB = sycl::malloc_device<int>(N, q);
  int *devR = sycl::malloc_device<int>(N, q);

  q.copy(a.data(), devA, N);
  q.copy(b.data(), devB, N);
  q.wait();

  q.parallel_for(N, [=](sycl::id<1> idx) {
    devR[idx] = devA[idx] + devB[idx];
  }).wait();

  q.copy(devR, r.data(), N).wait();

  sycl::free(devA, q);
  sycl::free(devB, q);
  sycl::free(devR, q);

  assert(r == expected);
}
* Device allocations follow a copy-in, compute, copy-out pattern.
* `malloc_device` allocates memory in a device's memory. * Since these allocations are in a remote memory, the only thing acessible on the host is the USM pointers returned by the `sycl::malloc_device` calls.
* Data needed for the kernel's execution must be copied to the device before execution begins.
* Copying data to a device is an asynchronous operation, so we explicitly tell the host to wait for the events to be resolved. * Copying `a` and `b` can happen concurrently, so we don't need to wait, but the kernel cannot execute until the contents of `a` and `b` are in device memory.
* The kernel reads and writes the device pointers. * You a USM pointer with a subscript `operator[]`, in this example we are passing the `sycl::id` of the work item.
* Kernel execution is asynchronous from the host, just like copying memory. * Calling `wait` forces the host to synchronize with the device, this prevents race conditions.
* Free device allocations when done to avoid memory leaks.
#### Malloc Shared 

#include <sycl/sycl.hpp>
#include <vector>

int main() {
  constexpr int N = 5;
  std::vector<int> expected{6, 6, 6, 6, 6};
  sycl::queue q;

  int *a = sycl::malloc_shared<int>(N, q);
  int *b = sycl::malloc_shared<int>(N, q);
  int *r = sycl::malloc_shared<int>(N, q);

  for (int i = 0; i < N; ++i) {
    a[i] = i + 1;
    b[i] = N - i;
  }

  q.parallel_for(N, [=](sycl::id<1> idx) {
    r[idx] = a[idx] + b[idx];
  }).wait();

  std::vector<int> result(r, r + N);
  assert(result == expected);

  sycl::free(a, q);
  sycl::free(b, q);
  sycl::free(r, q);
}
* Shared memory removes the explicit copies of the device example.
* `malloc_shared` allocates memory that migrates between host and device automatically.
* Shared memory is host-accessible, so we write the inputs directly, with no `copy`.
* The device accesses the same pointers. * The data must still be copied between host and device, but you don't define that explicitly, the runtime decides when. * Shared memory accesses may be slower depending on platform.
